## Recorrido propuesto por el titular

El titular plantea crear un «plugin» para utilizar desde ChatGPT. El nombre describe su propuesta; el mecanismo que permita realizarla y su disponibilidad deben comprobarse.

1. El cliente se registra en GitHub o utiliza su cuenta existente.
2. El titular inicia la transferencia de propiedad del repositorio de la web al cliente.
3. El cliente recibe y acepta la invitación o aviso correspondiente. El uso de correo y las pantallas exactas de aceptación están pendientes de validación.
4. El cliente vuelve al mecanismo de conexión con ChatGPT, autoriza el acceso mediante las pantallas oficiales disponibles y selecciona el repositorio de su web.
5. Desde el chat solicita cambios de contenido. Falta validar cómo se revisan, guardan y publican esos cambios sobre la web correcta.

Este recorrido es una propuesta funcional, no una guía de uso verificada. No presupone que ChatGPT admita hoy un plugin instalable con esas funciones ni que todos los pasos puedan completarse como se han descrito.

## Comprobaciones necesarias antes de ofrecer instrucciones

- Identificar qué mecanismo soportado permite acceder a GitHub desde ChatGPT y efectuar las operaciones necesarias, con sus requisitos de cuenta y disponibilidad.
- Probar la transferencia con cuentas de prueba: aceptación, propietario final y acceso posterior al repositorio.
- Comprobar que el cliente puede identificar y autorizar únicamente el repositorio previsto, y que la conexión sigue funcionando después de la transferencia.
- Validar un cambio de contenido de principio a fin: solicitud, revisión, modificación, publicación y recuperación de la versión anterior.
- Verificar el recorrido desde el móvil y documentar sus límites con resultados observados.

El titular mencionó con duda «copiar un código y pegarlo en ChatGPT». **No se considera un paso confirmado.** La autorización debe realizarse mediante el flujo oficial que corresponda; no se solicitarán contraseñas, tokens ni códigos secretos en el chat. Si una pantalla oficial requiere una confirmación, habrá que comprobar qué es y dónde se introduce antes de escribir instrucciones.

Mantener el estado interno como pendiente hasta completar estas comprobaciones. Actualizar el texto comercial o este documento no constituye una implementación ni una prueba de funcionamiento.
